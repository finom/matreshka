# Вступ

Matreshka.js прив’язує властивості об’єктів JavaScript до DOM-елементів. HTML береться звідти ж, звідки й зараз: із серверного шаблону, CMS або статичного файлу. Matreshka знаходить елементи за селектором і підтримує їх у відповідності з властивостями.

## Що вона вміє

- **Двостороння прив’язка.** [`bindNode`](/ua/api/matreshka/bind-node/) прив’язує властивість до одного або кількох елементів. Присвоїли значення властивості — оновилися елементи. Ввели текст у поле, позначили чекбокс чи вибрали пункт списку — оновилася властивість. Що саме показує елемент (текст, атрибут, клас, стиль), визначає [байндер](/ua/api/binders/). Поля форм мають байндер за замовчуванням.
- **Обчислювані значення.** [`calc`](/ua/api/matreshka/calc/) робить властивість залежною від інших і перераховує її, щойно вони змінюються.
- **Перетворення значень.** [`mediate`](/ua/api/matreshka/mediate/) пропускає кожне нове значення властивості через функцію, наприклад `Number`.
- **Події.** [`on`](/ua/api/matreshka/on/) підписується на зміни властивостей (`change:x`), на DOM-події прив’язаних елементів (`click::x`) і на ваші власні події.
- **Списки.** [`Matreshka.Array`](/ua/api/matreshka-array/) відмальовує по елементу на кожен пункт масиву й оновлює DOM під час виклику `push`, `splice`, `sort` та інших методів. [`Matreshka.Object`](/ua/api/matreshka-object/) — для даних з відомим набором ключів.
- **URL і форми.** `matreshka/router` прив’язує властивості до частин URL, `matreshka/parse-form` — поля форми до властивостей за їхніми іменами.

## Як це працює

Прив’язка перетворює властивість на аксесор — пару з геттера й сеттера. Сеттер записує значення в прив’язані елементи, а обробник DOM-події на кожному елементі записує значення елемента назад у властивість. Ні віртуального DOM, ні шаблону, який треба перемальовувати: зміна йде від властивості просто до її елементів. У [FAQ](/ua/faq/) цю ідею показано на десятку рядків коду.

Якщо властивість ще не має значення, `bindNode` бере його з елемента. Тому форма, яку сервер віддав уже заповненою, одразу стає початковим станом об’єкта.

## Два стилі

Функції приймають першим аргументом будь-який об’єкт:

```js
import { bindNode, calc } from 'matreshka';

const user = {};
bindNode(user, 'name', '.name');
calc(user, 'greeting', 'name', (name) => `Привіт, ${name}`);
```

Клас [`Matreshka`](/ua/api/matreshka/) має ті самі функції у вигляді методів, і об’єктом слугує `this`:

```js
import Matreshka from 'matreshka';

class User extends Matreshka {
  constructor() {
    super();
    this.bindNode('name', '.name');
    this.calc('greeting', 'name', (name) => `Привіт, ${name}`);
  }
}
```

Стилі можна поєднувати. Функції зручні, коли на готову сторінку треба додати кілька прив’язок; класи — для більших частин, і `Matreshka.Array` вміє відмальовувати їх списком.

## Де вона доречна

- **HTML, який відмальовує сервер** (Rails, Django, Laravel, WordPress). Розмітка лишається такою, якою її віддав сервер, а скрипт додає поведінку.
- **Віджет на чужій сторінці.** [`bindSandbox`](/ua/api/matreshka/bind-sandbox/) і селектори `:sandbox` обмежують пошук елементів коренем віджета.
- **Старий застосунок**, якому потрібна нова поведінка без переписування.
- **Один HTML-файл** з одним тегом `<script>` і без збирання.

## Що залишається на вашому боці

У Matreshka немає системи компонентів, мови шаблонів і кроку збирання. [`Matreshka.Array#itemRenderer`](/ua/api/matreshka-array/item-renderer/) приймає рядок HTML, селектор або функцію. Як розкласти код по об’єктах і файлах, вирішуєте ви.
