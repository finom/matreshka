# Введение

Matreshka.js привязывает свойства объектов JavaScript к DOM-элементам. HTML берётся оттуда же, откуда и сейчас: из серверного шаблона, CMS или статического файла. Matreshka находит элементы по селектору и поддерживает их в соответствии со свойствами.

## Что она умеет

- **Двусторонняя привязка.** [`bindNode`](/ru/api/matreshka/bind-node/) привязывает свойство к одному или нескольким элементам. Присвоили значение свойству — обновились элементы. Ввели текст в поле, отметили чекбокс или выбрали пункт списка — обновилось свойство. Что именно показывает элемент (текст, атрибут, класс, стиль), определяет [байндер](/ru/api/binders/). У полей форм байндер есть по умолчанию.
- **Вычисляемые значения.** [`calc`](/ru/api/matreshka/calc/) делает свойство зависимым от других и пересчитывает его при их изменении.
- **Преобразование значений.** [`mediate`](/ru/api/matreshka/mediate/) пропускает каждое новое значение свойства через функцию, например `Number`.
- **События.** [`on`](/ru/api/matreshka/on/) подписывается на изменения свойств (`change:x`), на DOM-события привязанных элементов (`click::x`) и на ваши собственные события.
- **Списки.** [`Matreshka.Array`](/ru/api/matreshka-array/) отрисовывает по элементу на каждый пункт массива и обновляет DOM при вызове `push`, `splice`, `sort` и других методов. [`Matreshka.Object`](/ru/api/matreshka-object/) — для данных с известным набором ключей.
- **URL и формы.** `matreshka/router` привязывает свойства к частям URL, `matreshka/parse-form` — поля формы к свойствам по их именам.

## Как это работает

Привязка превращает свойство в аксессор — пару из геттера и сеттера. Сеттер записывает значение в привязанные элементы, а обработчик DOM-события на каждом элементе записывает значение элемента обратно в свойство. Ни виртуального DOM, ни шаблона, который нужно перерисовывать: изменение идёт от свойства прямо к его элементам. В [FAQ](/ru/faq/) эта идея показана на десятке строк кода.

Если у свойства ещё нет значения, `bindNode` берёт его из элемента. Поэтому форма, которую сервер отдал уже заполненной, сразу становится начальным состоянием объекта.

## Два стиля

Функции принимают первым аргументом любой объект:

```js
import { bindNode, calc } from 'matreshka';

const user = {};
bindNode(user, 'name', '.name');
calc(user, 'greeting', 'name', (name) => `Привет, ${name}`);
```

У класса [`Matreshka`](/ru/api/matreshka/) те же функции есть в виде методов, и объектом служит `this`:

```js
import Matreshka from 'matreshka';

class User extends Matreshka {
  constructor() {
    super();
    this.bindNode('name', '.name');
    this.calc('greeting', 'name', (name) => `Привет, ${name}`);
  }
}
```

Стили можно сочетать. Функции удобны, когда на готовую страницу нужно добавить несколько привязок; классы — для частей покрупнее, и `Matreshka.Array` умеет отрисовывать их списком.

## Где она уместна

- **HTML, который отрисовывает сервер** (Rails, Django, Laravel, WordPress). Разметка остаётся такой, какой её отдал сервер, а скрипт добавляет поведение.
- **Виджет на чужой странице.** [`bindSandbox`](/ru/api/matreshka/bind-sandbox/) и селекторы `:sandbox` ограничивают поиск элементов корнем виджета.
- **Старое приложение**, которому нужно новое поведение без переписывания.
- **Один HTML-файл** с одним тегом `<script>` и без сборки.

## Что остаётся на вашей стороне

В Matreshka нет системы компонентов, языка шаблонов и шага сборки. [`Matreshka.Array#itemRenderer`](/ru/api/matreshka-array/item-renderer/) принимает строку HTML, селектор или функцию. Как разложить код по объектам и файлам, решаете вы.
